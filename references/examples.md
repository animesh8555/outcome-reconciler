# Delivery-boundary examples

All examples are synthetic; they are not claims of product evaluation results.

## Marketplace

Goal: publish a free skill and confirm it loads. Criteria: package accepted, listing approved, live listing free, complete instructions retrieved by the intended agent. A successful upload cannot satisfy the last three. A connected badge cannot satisfy retrieval.

## Software release

Goal: fix a user-visible bug. Criteria: original symptom reproduced, fix applied, relevant regression check passed, intended user flow verified. If only a unit check is available, report that scope rather than claim the user flow passed.

## Connected tool

Goal: retrieve a document through a connector. Criteria: intended account authorized, tool visible in the intended client, requested document retrieved, result matches the expected document. An authorization page or a generic success response alone is insufficient.

Use the Pro JSON templates for structured reports. The templates deliberately start with not checked criteria and are not completed evidence.
